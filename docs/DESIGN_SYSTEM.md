# DanceMirror Design System

## Changelog

- v0.5 (2026-07-17)：沉淀方向三高保真 Demo 的柔和中性色、双视频工作台、差异节点、状态组件与响应式规则；移除评分视觉
- v0.4 (2026-07-17)：双视频左右并排，加入公共时间轴与 AI 建议面板

## 1. 设计原则

DanceMirror 面向长期练舞的 C 端用户，界面应当像一位克制、友好的舞蹈老师：先肯定做对的部分，再指出一个明显问题，并给出下一遍可以执行的练法。

- 主任务优先：每屏只突出一个当前动作
- 柔和但不幼稚：大面积浅灰白，彩色只承担角色和行动含义
- 视频优先：深色画面承载视频，所有视频保持完整画面，禁止裁掉四肢
- 不用评分制造压力：报告只展示 1–3 个按重要性排序的差异
- 反馈可解释：推理依据默认收起，识别质量一般时明确标记“仅供参考”

## 2. 设计变量

### 颜色

| Token | 值 | 用途 |
|---|---:|---|
| `--color-canvas` | `#f3f4f6` | 应用背景 |
| `--color-surface` | `#ffffff` | 页面和卡片 |
| `--color-ink` | `#17181a` | 标题、深色按钮、视频底 |
| `--color-text` | `#313338` | 正文 |
| `--color-muted` | `#72757d` | 辅助说明 |
| `--color-border` | `#dedfe3` | 边框与分隔 |
| `--color-teacher` | `#22c7e8` | 老师视频、角色标签 |
| `--color-user` | `#ff5b86` | 用户视频、角色标签 |
| `--color-action` | `#b9f43b` | 核心成功操作、高亮 |
| `--color-warning` | `#ff9e44` | 中等差异、提醒 |
| `--color-danger` | `#ec4c60` | 严重差异、删除、错误 |

同一页面最多使用一个大面积强调色。青色和珊瑚色用于区分视频角色，不表示对错；红、橙、黄只用于差异严重程度。

### 字体

- 字体栈：`Inter, SF Pro Display, PingFang SC, Microsoft YaHei, sans-serif`
- 页面标题：28–40px / 700
- 区块标题：20–26px / 700
- 正文：15–16px / 400–500
- 标签与辅助文案：12–13px / 600
- 移动端正文不得小于 14px；所有中文必须是可选中、可编辑的文本

### 空间、圆角与阴影

- 间距基线：4px；常用值 8、12、16、20、24、32、48
- 控件高度：44–52px，移动端点击区域不小于 44px
- 圆角：按钮 12px、输入/小卡片 14px、主卡片 18–22px、弹窗 24px
- 阴影只用于浮层与重点卡片：`0 18px 50px rgb(19 22 31 / 10%)`
- 桌面内容最大宽度 1120px；移动端页面边距 16px

## 3. 核心组件

### Button

- `Primary`：荧光绿底深色字，当前页面唯一主行动
- `Secondary`：白底细边框，用于更换、返回、重试
- `Text`：无底色，用于低优先操作
- `Danger`：红底白字，只用于最终删除确认
- 状态：default、hover、pressed、focus-visible、disabled、loading

### Video Upload Card

- 变体：teacher / user；empty / selected / error / disabled
- 已选择态展示视频预览、真实文件名、时长、大小、删除入口
- 两段视频都存在并完成处理后才启用“立即体验AI分析舞蹈动作”

### Comparison Workspace

- 两段视频始终等权并排，窄屏也不改为上下堆叠
- 视频使用 `object-fit: contain`，角色用青/珊瑚标签区分
- 公共进度条同时控制两段视频，支持播放、逐帧、0.5–1.25 倍速和 4 秒循环
- 报告生成后在进度条叠加差异区间；红 > 橙 > 黄，播放头进入区间时高亮放大

### Subject Selection

- 检测到多人后先选老师，再选用户
- 代表帧和候选卡片必须显示当前选中状态
- “手动框选”使用覆盖真实视频画面的可拖拽框选层，支持触控与鼠标；确认后在人物选择页和双视频工作台持续显示锁定区域
- 手机框选层占用动态视口，确认与取消按钮避开底部安全区并始终可达

### Process Stepper

- 状态：pending、active、complete、error
- 每一步有真实任务文案；处理中持续显示当前动作，不使用假百分比
- 用户可在处理/分析期间更换视频或取消任务

### Issue Card

- 结构：时间与优先级 → 问题标题 → 肯定 → 表现 → 影响 → 练法 → 鼓励
- 激活卡片与当前时间轴节点同步
- 识别质量一般显示“仅供参考”；判断依据使用 `details` 默认收起

### Overlay

- 隐私说明用底部抽屉；不可逆操作用确认弹窗；轻量结果用 Toast
- 所有浮层支持遮罩点击或 Escape 关闭，危险操作除外时须保留明确取消按钮

## 4. 状态与响应式

- 全流程覆盖：默认、加载、空、错误、禁用、成功、权限/浏览器能力不足
- 上传限制：MP4/MOV、单个不超过 3 分钟和 500MB
- 手机为首要场景；560px 起提升表单密度，760px 起使用双栏内容，1080px 起限制最大内容宽度
- 支持横竖屏与两个视频方向不一致；任何断点都不裁切身体
- 首发验收：iPhone Safari、主流 Android Chrome、微信内置浏览器；桌面 Chrome 为补充

## 5. 动效与可访问性

- 页面切换 180–240ms，节点激活和 Toast 120–180ms，不使用持续炫技动效
- 支持 `prefers-reduced-motion`
- 键盘焦点使用清晰外圈；图标按钮有 `aria-label`；状态更新使用 `aria-live`
- 颜色不作为唯一信息通道，严重程度同时提供文案与顺序

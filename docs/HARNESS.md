# DanceMirror Harness Guide

## Changelog

- v0.2 (2026-07-10): 即来即用，去掉登录/建议/历史，更新质量门槛
- v0.1 (2026-07-01): 初始版本

Harness 工程的目标是给 AI 一个固定工作台，让 Codex 每次都在产品边界、设计边界和质量边界里开发。

当前阶段：真实上传、媒体处理、结构化动作分析、受控模型和规则 fallback 已接入；后续重点是外部视频、多端浏览器、Docker/云资源与部署验收。

## 1. 工作方式

每次让 Codex 开发时，用这个模板：

```text
请先阅读 docs 下的 PRD、DESIGN_SYSTEM、TECH_SPEC、AI_SPEC、TASKS、HARNESS。
不要立即写代码。
先输出你对本次任务的理解、将修改的文件、验收方式。
确认后再实施。
```

如果任务很小，可以直接说：

```text
请按 docs/HARNESS.md 的约束完成 docs/TASKS.md 里的 Task 1。
完成后运行可用的检查，并说明改了什么。
```

## 2. AI 开发边界

Codex 应该：

- 优先遵守本仓库文档
- 保持移动端优先
- 保持即来即用，不引入登录注册
- 先完成 AI 复盘闭环，不扩展社区和课程
- 把 mock 数据集中管理
- 每次修改后运行 `npm run check` 并说明结果

Codex 不应该：

- 擅自改产品定位
- 一次性引入复杂后端、登录、支付
- 把穿搭做成商城
- 把产品变成通用运动平台
- 用泛泛评分替代差异解释
- 引入用户认证、历史记录等非 MVP 功能

## 3. 质量门槛

每个功能完成后必须通过：

```bash
npm run check
```

这会依次运行：

- `npm run lint` — ESLint + HTMLHint + Stylelint
- `npm run test` — Vitest 单元测试 + Contract Test

手动检查：

- 页面是否能打开
- 移动端是否无横向滚动
- 上传/删除/重新上传是否可用
- loading/error/empty 状态是否存在
- 报告是否符合 `AI_SPEC.md`
- 双视频播放是否保持老师有声、用户静音，拖动和倍速后规则不变
- 长视频播放时同步监控、时间轴 UI 与姿态 Canvas 是否互不阻塞
- 3 个动作差异卡片是否可以分别展开和收起

## 4. 文案约束

所有反馈都要符合：

- 具体
- 温和
- 可执行
- 不攻击身材
- 不做医疗诊断

## 5. 版本节奏

推荐版本：

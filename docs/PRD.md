## 1. 产品背景与目标

### 1.1 产品背景

DanceMirror 是面向 C 端舞蹈爱好者的双视频复盘工具。用户上传老师示范视频和自己的练习视频，系统完成视频处理、人物锁定、音轨校准和动作差异分析，再用接近舞蹈老师上课的语言给出反馈。

产品不是考试系统，也不是动作评分工具。它优先帮助用户理解一个自己能够明显感知的问题，并知道下一次具体应该怎么练。

### 1.2 MVP 核心成功结果

【目标需求】一次有效的 MVP 复盘必须满足：

1. 至少指出 1 个用户非常明显、甚至自己能够感知的动作问题。
2. 使用用户容易理解、接近舞蹈老师日常教学的语言描述。
3. 给出与该问题直接相关、能够执行的练习建议。
4. 用户可以通过时间轴差异节点回到对应片段，验证“差异定位—回放—分析”的闭环。

【目标需求】本阶段验证两件事：

- 反馈是否精准。
- 建议是否可执行。

用户是否愿意再次练习不是本阶段产品成功指标。

### 1.3 产品原则

- 解释优先于评分。
- 明显问题优先于细微差异。
- 可执行建议优先于技术诊断。
- 可信结果才输出明确结论。
- 不向用户展示原始坐标、模型调试信息或复杂置信度数值。
- 不攻击身材，不做医疗或康复诊断。

## 2. 目标用户与核心场景

### 2.1 目标用户

【目标需求】核心用户是同时拥有老师示范视频和本人练习视频，希望课后独立复盘的舞蹈爱好者。

本版本不限定具体舞种、性别、年龄和舞龄，但默认用户：

- 能够从本地相册或文件中选择视频。
- 不需要理解姿态识别、模型、DTW 或音轨互相关。
- 希望看到具体时间点和具体动作建议，而不是技术指标。

### 2.2 核心场景

1. 用户完成一段练习后，希望知道自己和老师最明显的差异。
2. 用户的视频起点、方向、画幅或时长与老师视频不一致。
3. 视频中可能出现其他人物，需要明确选择本次分析对象。
4. 自动音轨匹配失败时，用户需要手动指定同一个动作起点。
5. 用户希望从反馈直接跳回差异片段，边看边理解。
6. 用户若想再次比对，可以替换视频并重新生成，不需要独立“重新比对”功能。

### 2.3 核心痛点

- 人工拖动两段视频很难找到同一拍和同一动作。
- 多人画面中无法确认系统分析的是谁。
- 用户能感到“看起来不一样”，但不知道具体差在哪里。
- 泛化评分无法解释问题，也缺少统一、可信的满分标准。
- 技术化反馈难以转化为下一次练习动作。

## 3. 产品范围

### 3.1 MVP 范围

【目标需求】MVP 包含：

- 移动端优先的无登录 H5。
- 老师视频和用户视频双上传，二者均为必需。
- MP4、MOV 文件校验、上传和服务端统一转码。
- 自动音轨对齐及失败后的手动校准。
- 老师和用户视频的目标人物检测、选择与持续跟踪。
- 共享时间轴、同步播放、拖动和差异节点。
- 姿态识别、动作差异和分析质量控制。
- 1–3 条按重要性排序的问题。
- 非评分式的自然语言反馈和练习建议。
- 受控后端模型服务和非大模型结构化报告兜底。
- 追踪丢失区间提示。
- 当前任务中的视频替换、取消和重新生成。
- 本次数据的隐私说明和删除能力。

### 3.2 非 MVP 范围

- 登录、注册、头像账户体系。
- 历史报告、成长曲线和跨设备同步。
- 同时分析、评分或排名多个人。
- 为不同人物建立多个报告分支。
- 独立评分页、综合分、四维分和排行榜。
- 自动人物编号。
- 热力图、推测性轨迹和红绿正确性路径。
- 视角或透视校正。
- 社区、课程、题库、会员和支付。
- 复杂多模型管理平台。
- 平板、旧版浏览器和小众视频格式的完整兼容承诺。
- “重新比对”独立功能。

## 4. 视频输入与处理规则

### 4.1 双视频要求

【目标需求】老师视频和用户视频必须同时存在。缺少任一视频时：

- 不启动音轨对齐。
- 不启动人物分析。
- 不允许生成报告。
- 页面就近提示需要补充哪一段视频。

【目标需求】老师视频必须包含可识别的背景音乐，并作为音轨与共享时间轴基准。

【目标需求】用户视频建议包含音轨，但不是强制条件。用户视频无音轨、音质过差或无法匹配时进入手动校准。

### 4.2 文件规格

| 项目 | MVP 规则 |
|---|---|
| 单文件最大时长 | 3 分钟 |
| 单文件最大大小 | 500MB |
| 输入格式 | MP4、MOV |
| 服务端输出 | MP4，H.264 + AAC |
| 输出上限 | 最高 1080p、30fps |
| 画面方向 | 横屏、竖屏、两段方向不一致均支持 |
| 展示原则 | 保持完整画面，不为统一比例裁掉四肢 |

客户端先校验文件扩展名、大小和可读取的时长；服务端继续校验真实容器、编码、音轨和文件完整性。客户端校验通过不代表服务端一定接受。

### 4.3 上传与转码

【目标需求】用户选择视频后立即显示本地预览，同时开始上传。

视频状态：

```text
empty
→ validating
→ uploading
→ uploaded
→ transcoding
→ ready
```

失败状态：

```text
invalid_format
too_large
too_long
upload_failed
decode_failed
transcode_failed
teacher_audio_missing
```

每个失败状态必须提供明确原因及“重新选择视频”入口。

### 4.4 替换和删除

【目标需求】音轨对齐或分析期间允许替换、删除视频。

规则：

1. 用户点击替换或删除时，提示“此操作会取消当前处理”。
2. 用户确认后，客户端取消当前上传、对齐或分析任务。
3. 服务端将旧任务标记为 cancelled；旧任务结果不得回写页面。
4. 与被替换素材相关的转码、人物选择、音轨、差异节点和报告全部失效。
5. 新视频 ready 后重新进入自动处理。

## 5. 核心用户流程

### 5.1 主流程

```text
进入单页
→ 添加老师视频和用户视频
→ 客户端校验、上传、服务端转码
→ 自动音轨对齐 + 人物检测并行执行
→ 若检测到多人：选择本次跟踪人物
→ 若自动音轨失败：手动选择对应动作起点
→ 人物已锁定 + 音轨已校准
→ 开始动作分析
→ 生成结构化差异并返回 H5 当前会话
→ 受控模型转化为舞蹈老师式反馈
   ├─ 模型成功：展示自然语言报告
   └─ 模型失败：H5 使用当前会话的结构化结果展示兜底报告
→ 在共享时间轴查看 1–3 个差异节点
→ 播放进入节点区间时自动展示对应分析
```

### 5.2 并行处理规则

- 视频上传完成后自动开始转码。
- 两段视频均具备可处理音轨后，自动开始音轨对齐，并明确显示“正在自动对齐”。
- 人物检测不必等待音轨对齐完成。
- 自动对齐失败不阻断人物选择。
- 只有两段目标人物均锁定、两段视频 ready、音轨已自动或手动校准后，才允许开始动作分析。

### 5.3 再次生成

【目标需求】MVP 不提供“重新比对”按钮。

用户希望重新生成时：

- 替换老师视频或用户视频。
- 等待新素材完成处理。
- 再次点击生成按钮。

若用户没有替换素材，再次点击生成视为对当前素材重新发起分析；新任务开始后旧任务结果标记为 stale，不得与新任务混用。

## 7. 页面与功能说明

### 7.1 双视频上传区

- 固定区分“老师示范”和“我的练习”。
- 展示文件名、时长、大小、上传/转码进度和替换/删除入口。
- 空状态直接触发文件选择。
- 上传老师视频时提示“需包含清晰背景音乐”。
- 上传用户视频时提示“建议全身入镜、机位固定；无音轨时可手动校准”。
- 横竖屏均以 contain 方式完整展示，不裁切人物四肢。

### 7.2 自动处理状态区

按用户语言展示：

- 正在上传视频。
- 正在统一视频格式。
- 正在自动寻找同一段音乐。
- 正在识别需要跟踪的人物。
- 已完成自动对齐。
- 自动对齐失败，需要手动确认同一动作起点。

不向普通用户展示转码参数、模型名称、相关系数或关键点坐标。

### 7.3 人物检测与锁定

【目标需求】老师和用户视频都必须存在明确的目标人物。

单人场景：

- 系统自动锁定唯一稳定人物。
- 视频上显示可见的锁定轮廓和“已选择此人物”状态。
- 用户可以主动重新选择。

多人场景：

- 分别对老师视频和用户视频判断是否多人。
- 展示能够代表各候选人物的代表帧或可点击区域。
- 用户只选择本次需要跟踪的一个人物。
- 选择结果用于后续整段持续跟踪，不创建多个人物报告分支。

无法稳定锁定：

- 不输出该人物的明确动作结论。
- 提示重新选择目标人物或更换视频。

### 7.4 自动音轨对齐

- 两段视频具备可处理条件后自动开始。
- 老师音轨和老师时间轴是基准。
- 系统调整用户视频起始时间，使同一音乐和动作区间对齐。
- 对齐中必须有持续可见的 loading 状态。
- 对齐成功显示“已自动对齐”，不要求用户理解偏移秒数。
- 对齐低可信或失败时显示手动校准入口。

### 7.5 手动音轨校准

用户可通过以下任一方式指定对应动作：

- 分别拖动老师和用户视频到同一动作起点后确认。
- 在两段视频中分别选择“以此处作为对应起点”。

系统根据两个起点计算偏移，并提供同步预览。用户确认后状态变为 aligned_manual。

如果老师视频无可用音轨，提示更换老师视频；不以无音轨老师视频进入正式分析。

### 7.6 同步比对工作台

- 使用老师时间轴作为共享时间基准。
- 播放、暂停、拖动、变速和时间步进同时驱动两段视频。
- 用户视频按音轨校准结果映射到老师时间。
- 画幅方向不一致时各自保持完整画面。
- 时间步进若尚未实现真实帧感知，文案必须写成具体时间步进，不得宣称精确逐帧。

### 7.7 差异节点

【目标需求】分析生成 1–3 个差异问题，并在共享进度条叠加节点。

节点规则：

| 严重程度 | 视觉语义 | 用途 |
|---|---|---|
| high | 红色节点 | 最影响整体观感、用户最容易感知的问题 |
| medium | 橙色节点 | 明显但优先级次于 high |
| low | 黄色节点 | 可在主要问题之后优化 |

- 颜色只表示差异严重程度，不表示人格化的“对/错”评价。
- 节点同时使用形状、尺寸或文本标签，不只依赖颜色。
- 节点覆盖一个时间区间，而不是只有单个时间点。
- 播放位置进入节点区间时，节点高亮放大并自动激活对应分析。
- 播放离开区间时取消激活；用户主动点击节点时立即定位到区间起点。
- 如果多个区间重叠，优先激活严重程度更高的节点；同级时优先开始时间更早的节点。

### 7.8 追踪丢失区间

- 短暂丢失由系统跳过、插值或补偿，不频繁打扰用户。
- 持续丢失且影响分析时，在时间轴增加独立的中性警告区间，不与红/橙/黄差异节点混淆。
- 文案示例：“用户视频 00:18—00:21 未识别到完整身体”。
- 丢失区间不生成具体动作结论。
- 严重时停止分析相关片段，并提供“重新选择人物”“重新校准”“更换视频”入口。

### 7.9 页面内报告

报告信息顺序：

1. 一句话总结。
2. 最重要、最明显的问题。
3. 1–3 个按重要性排序的问题。
4. 每个问题的老师表现、用户表现和练习建议。
5. 可按需展开的“为何这样判断”。
6. 本次练习建议。

【目标需求】MVP 不展示综合分、姿态分、节奏分、幅度分或控制分。

【目标需求】“为何这样判断”展示的是可解释依据摘要，不是模型原始思维链、原始坐标或调试数据。

### 7.10 隐私与数据

- 页面在上传前说明视频将上传至服务端用于转码和本次分析。
- 用户无需提供模型 API Key。
- 页面提供“删除本次数据”入口。
- MVP 不提供用户可见历史记录。
- 数据默认在任务结束后保留 24 小时；服务端定时清理为主，OSS 生命周期规则只作为兜底。
- 用户主动删除或自动清理都必须覆盖原始视频、转码文件、音频、抽帧、中间结果、关键点、任务和报告。
- 生产视频使用私有阿里云 OSS Bucket 和短期签名 URL；任务、报告及文件索引存入 PostgreSQL，异步任务使用 Redis。

## 8. 功能触发、处理与输出

| 功能 | 触发条件 | 处理逻辑 | 输出 |
|---|---|---|---|
| 选择视频 | 点击任一空上传区 | 客户端校验格式、大小、时长 | 本地预览或就近错误 |
| 上传转码 | 客户端校验通过 | 上传并转为 H.264 + AAC、最高 1080p/30fps | ready 或转码错误 |
| 自动音轨对齐 | 两段视频可处理 | 以老师音乐和时间轴为基准匹配用户视频 | aligned_auto、manual_required 或 error |
| 手动校准 | 自动失败/用户主动调整 | 选择两段对应动作起点并计算映射 | aligned_manual |
| 单人锁定 | 只检测到一个稳定人物 | 自动选择并持续跟踪 | locked |
| 多人选择 | 任一视频检测到多人 | 展示候选，用户选定一个人物 | selectedTrackId |
| 开始分析 | 双视频 ready、已校准、两侧人物已锁定 | 姿态、动作差异、质量控制 | structuredAnalysis |
| 模型反馈 | 结构化分析完成 | 服务端调用唯一主模型，超时重试 | naturalLanguageReport |
| 模型兜底 | 模型失败或超时 | 服务端根据已校验的结构化分析生成规则报告 | fallbackReport |
| 节点激活 | 播放进入差异区间/点击节点 | 同步定位视频并选择对应问题 | 节点放大、分析卡展示 |
| 追踪丢失 | 持续丢失超过内部质量阈值 | 记录区间并停止该区间结论 | trackingGap 提示 |
| 替换/删除 | 用户确认取消当前处理 | 取消旧任务并清空派生数据 | 回到 partial/empty |
| 删除本次数据 | 用户确认删除 | 删除任务、视频和报告数据 | cleared |

---

## 9. 状态模型与页面跳转

### 9.1 页面状态

```text
upload:
  empty | partial | validating | uploading | transcoding | ready | error

alignment:
  idle | working | ready_auto | manual_required | calibrating | ready_manual | error

subject:
  detecting | single_locked | selection_required | locked | lost | error

analysis:
  idle | validating | processing | model_summarizing | success | fallback | error | cancelled

report:
  empty | ready | stale
```

### 9.2 关键转移

- 替换或删除任一视频：取消当前任务，重置 alignment、subject、analysis 和 report。
- 自动对齐失败：保留已上传视频，进入 manual_required。
- 多人检测：只阻断对应视频的人物锁定，不阻断另一侧检测。
- 模型失败：不进入全局 error，进入 fallback。
- 新分析开始：旧报告进入 stale，旧节点不可继续作为新任务结果。
- 清除本次数据：回到 upload.empty。

## 10. 数据结构

### 10.1 VideoAsset

| 字段 | 含义 |
|---|---|
| id | 服务端视频标识 |
| role | teacher 或 user |
| originalName | 原文件名 |
| inputFormat | mp4 或 mov |
| sizeBytes | 文件大小 |
| durationSec | 时长 |
| width/height | 原视频尺寸 |
| orientation | portrait、landscape、square |
| hasAudio | 是否存在音轨 |
| processingStatus | 上传/转码状态 |
| processedUrl | 本次任务使用的转码视频 |
| errorCode | 失败原因 |

### 10.2 SubjectSelection

| 字段 | 含义 |
|---|---|
| videoId | 所属视频 |
| selectedTrackId | 本次选择的人物轨迹标识 |
| selectionMode | automatic_single 或 manual_multiple |
| representativeFrameSec | 选择所用代表帧时间 |
| region | 归一化人物区域，用于初始化跟踪 |
| trackingStatus | locked、lost、invalid |

### 10.3 Alignment

| 字段 | 含义 |
|---|---|
| method | audio_auto 或 manual_anchor |
| teacherAnchorSec | 老师基准时间 |
| userAnchorSec | 用户对应时间 |
| offsetSec | 用户相对老师偏移 |
| sharedDurationSec | 可同步播放区间 |
| qualityStatus | reliable、manual_required、failed |

具体相关系数和数值置信度仅供内部质量控制，不直接展示给普通用户。

### 10.4 Mismatch

| 字段 | 必填 | 含义 |
|---|---|---|
| id | 是 | 问题标识 |
| startTimeSec | 是 | 老师共享时间轴上的开始时间 |
| endTimeSec | 是 | 区间结束时间 |
| title | 是 | 用户易懂的问题标题 |
| severity | 是 | high、medium、low |
| teacherObservation | 是 | 老师在该区间的可观察动作 |
| userObservation | 是 | 用户在该区间的可观察动作 |
| advice | 是 | 可执行建议 |
| qualityLabel | 是 | normal、reference_only |
| evidenceSummary | 否 | 折叠展示的判断依据摘要 |
| evidenceType | 否 | objective、inference、mixed |

规则：

- mismatches 数量为 1–3 条。
- 按 severity 与整体影响排序。
- confidence 可以存在于内部结构化分析，但不进入普通用户输出。
- 质量不足的片段不进入 mismatches，进入 trackingGaps。

### 10.5 TrackingGap

| 字段 | 含义 |
|---|---|
| videoRole | teacher 或 user |
| startTimeSec/endTimeSec | 丢失区间 |
| reasonCode | no_full_body、occluded、target_lost、low_visibility |
| recoveryActions | reselect_subject、recalibrate、replace_video |

### 10.6 Report

```text
Report
├─ id
├─ comparisonId
├─ createdAt
├─ source: model | structured_fallback
├─ title
├─ summary
├─ mismatches[1..3]
├─ trackingGaps[]
├─ practicePlan
│  ├─ title
│  └─ steps[]
└─ safetyNote
```

报告对象不包含面向用户的综合分或维度分。

## 11. 前后端责任边界

### 11.1 H5 客户端

- 文件预校验和本地预览。
- 上传进度、任务状态和错误展示。
- 人物候选选择与手动音轨校准输入。
- 双视频同步播放和差异节点交互。
- 在浏览器内完成首版姿态提取和结构化差异生成，只向服务端发送去除原始视频、帧和关键点后的结构化结果。
- 接收标准报告；模型失败时正常渲染服务端返回的规则兜底报告。
- 报告渲染、依据展开和本次数据删除。
- 不保存模型 Endpoint、Model 或 API Key。

### 11.2 服务端

- 视频上传接收、临时存储、转码和媒体校验。
- 基于 PostgreSQL 的匿名会话、视频索引、任务和报告持久化。
- 基于 Redis 的上传转码和报告生成持久化队列。
- MP4/MOV 媒体校验、FFmpeg H.264 + AAC 转码和错误状态。
- 结构化输入运行时校验、DeepSeek 调用、超时重试、备用模型和规则报告降级。
- OSS/本地磁盘存储适配、短期签名 URL、24 小时定时清理和主动删除。
- 首版姿态、人物跟踪和音轨对齐仍在 H5 执行；后续按真实视频压测结果决定是否迁入 Worker。

### 11.3 模型服务

- 输入是结构化分析结果，不是用户自行配置的模型参数。
- 首版接入 DeepSeek 官方 OpenAI-compatible API，默认 `deepseek-v4-flash`，失败后尝试 `deepseek-v4-pro`。
- 保留服务端模型适配接口，后续可以替换模型。
- 不建设多模型选择、路由、计费或管理平台。
- 模型失败不影响结构化兜底报告。

## 12. 空、加载、成功和错误状态

### 12.1 空状态

- 双视频均为空：分别引导添加老师视频和用户视频。
- 只有一段：已添加一侧显示 ready，另一侧提示“还需添加另一段视频”。
- 报告为空：不展示报告容器和差异节点。

### 12.2 加载状态

- 文件校验中。
- 上传中，显示进度。
- 转码中。
- 自动音轨对齐中。
- 人物检测中。
- 姿态与差异分析中。
- AI 正在整理反馈。

### 12.3 成功状态

- 视频可处理。
- 音轨已自动对齐/已手动校准。
- 人物已锁定。
- 分析完成。
- 本次数据已删除。

### 12.4 错误与恢复

| 场景 | 用户反馈 | 恢复动作 |
|---|---|---|
| 格式、大小、时长不符合 | 明确指出限制 | 重新选择 |
| 老师无音轨 | 老师视频需要清晰背景音乐 | 更换老师视频 |
| 用户无音轨 | 无法自动对齐 | 手动校准 |
| 自动匹配失败 | 未找到可靠的同一音乐位置 | 手动校准 |
| 多人未选择 | 请先选择需要分析的人物 | 打开人物选择 |
| 人物持续丢失 | 标记具体区间 | 重选、校准或换视频 |
| 转码失败 | 视频处理失败 | 重试上传或换视频 |
| 模型失败 | 已使用基础分析生成反馈 | 查看兜底报告 |
| 分析失败 | 说明失败阶段 | 重试或换视频 |
| 删除/替换处理中素材 | 当前处理将被取消 | 确认或返回 |

## 13. 异常与边界规则

1. 两个视频方向不一致：各自 contain 展示，共享时间轴不受影响。
2. 用户无音轨：保留手动校准，不直接判定视频不可用。
3. 老师音轨不可识别：不进入正式分析，要求更换老师视频。
4. 自动对齐中替换素材：旧任务取消，旧结果丢弃。
5. 多人中目标短暂被遮挡：系统尝试连续跟踪，不立即弹窗。
6. 持续追踪丢失：记录 trackingGap，不输出该区间明确动作结论。
7. 模型超时：按服务端策略重试，仍失败则返回兜底报告。
8. 报告只有 1 条问题：允许，只要它是最明显且可感知的问题。
9. 没有可信问题：不得为了凑数生成结论；提示当前视频条件不足，并给出改进拍摄或重选建议。
10. 用户重新发起分析：旧报告标记 stale，新旧节点不得混用。

## 14. 验收标准

### 14.1 产品结果

1. 一次成功报告输出 1–3 条问题，并按重要性排序。
2. 至少一条问题应是用户能够明显感知、可以通过回放验证的问题。
3. 每条问题包含老师表现、用户表现和可执行建议。
4. 反馈语言接近舞蹈老师日常教学，不以技术指标或泛化分数替代解释。
5. 产品验证记录分别评价“反馈是否精准”和“建议是否可执行”，不把复练意愿作为本阶段指标。

### 14.2 视频与处理

1. 老师和用户视频均为必需。
2. MP4、MOV、3 分钟以内、500MB 以内的视频能够进入上传流程。
3. 服务端输出 H.264 + AAC、最高 1080p/30fps 的处理视频。
4. 横竖屏和方向不一致时完整显示画面，不裁掉人物四肢。
5. 老师无有效音轨时阻止分析并提示更换。
6. 用户无音轨或自动匹配失败时能够完成手动校准。
7. 替换或删除视频会取消旧任务，旧结果不会回写。

### 14.3 人物锁定与质量

1. 老师和用户视频都存在目标人物状态。
2. 单人视频可以自动锁定，并允许用户重新选择。
3. 多人视频展示候选并要求用户选择一个人物。
4. 后续只分析被选择人物，不为其他人物生成报告。
5. 持续追踪丢失时，时间轴标记具体区间。
6. 质量一般的结论显示“仅供参考”；质量过低的区间不生成具体结论。

### 14.4 时间轴与报告

1. 差异节点数量与报告问题数量一致，为 1–3 个。
2. 节点区分 high、medium、low，并同时使用颜色以外的视觉编码。
3. 播放进入节点区间时节点高亮，底部自动展示对应分析。
4. 点击节点后双视频定位到对应区间。
5. 报告不展示综合分和四维评分。
6. “为何这样判断”默认折叠，展开后只显示依据摘要。
7. 没有“重新比对”按钮；用户通过替换视频再次生成。

### 14.5 后端与隐私

1. 用户界面不出现 Endpoint、Model 或 API Key 设置。
2. 服务端统一管理模型 Key、额度、超时、重试和任务状态。
3. 模型失败时仍能展示结构化兜底报告。
4. 页面在上传前说明服务端处理用途。
5. 用户能够删除本次视频、任务和报告数据。

### 14.6 首发兼容范围

优先验收：

- iPhone Safari。
- 主流 Android Chrome。
- 微信内置浏览器。
- 桌面 Chrome 作为补充。

暂不承诺：

- 平板。
- 旧版浏览器。
- 其他小众浏览器和视频格式。

## 17. 已确认产品决策

本版已关闭以下产品问题：

- MVP 成功结果：看懂一个明显问题并获得易懂、可执行建议。
- 老师视频：必须上传。
- 人物锁定：MVP 必需，老师和用户两侧都要支持。
- 音轨对齐：上传后自动执行，失败后手动校准。
- 问题数量：1–3 条，按重要性排序。
- 差异节点：叠加在共享进度条，进入区间自动激活分析。
- 判断依据：默认折叠，按需展开依据摘要。
- 评分：从 MVP 移除。
- 模型：服务端受控单模型，结构化报告兜底。
- 视频：最长 3 分钟、最大 500MB、MP4/MOV、服务端统一转码。
- 分析中替换视频：允许，自动取消旧任务。
- 重新比对：不做独立功能。
- H5 保存：不提供用户历史；保留隐私说明和删除本次数据能力。
- 多人：只选择并分析一个目标人物，不做多人报告。
- 置信度：内部质量控制，不展示原始数值。
- 追踪丢失：持续丢失必须标记区间并提供恢复动作。
- 验证指标：反馈精准、建议可执行。

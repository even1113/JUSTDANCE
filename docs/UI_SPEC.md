# DanceMirror 页面级 UI 与交互规格

> 依据：`docs/PRD.md` v0.4、`docs/REQUIREMENT_REVIEW.md` v0.2、当前 H5 原型。
> 用途：作为 Figma 页面设计、交互原型和前端实现的共同基线。
> 注意：本文描述的是目标体验；当前代码尚未完全实现服务端上传转码、受控模型、多人候选、严重度节点、取消评分和数据删除。

## 0. 规格原则

- 产品是无登录、无业务路由的移动端优先单页 H5。
- Figma 中按关键页面状态拆成独立 Frame，但实现仍可使用同一页面内的状态切换和弹层。
- 所有文字必须使用可编辑的原生 Text 图层，不得转轮廓或合并为图片。
- 普通用户界面不得出现 Endpoint、Model、API Key、DTW、MediaPipe、关键点坐标等技术配置。
- 不展示综合分、姿态分、节奏分、幅度分或控制分。
- 反馈先讲最明显的问题，再讲练习方法；判断依据默认折叠。
- 差异严重度可用红、橙、黄，但不得把颜色写成“正确/错误”；必须同时提供形状、尺寸或文字标签。

### 1.1 必须制作的关键状态 Frame

- P01：双空、仅老师、仅用户、文件校验错误。
- P02：上传中、转码中、自动对齐中、人物检测中、部分失败。
- P03：老师多人、用户多人、单人自动锁定后重新选择、无法稳定锁定。
- P04：未选起点、只选老师、双起点已选、同步预览、校准失败。
- P05：全部就绪、仅供参考提示、追踪状态异常。
- P06：结构化分析、AI 整理反馈、模型失败转兜底、取消确认。
- P07：默认报告、节点激活、依据展开、追踪丢失区间、仅 1 条问题。
- P08：默认说明、删除确认、删除中、删除成功、删除失败。
- P09：浏览器不支持、网络中断、任务失效、服务不可用。

## 2. 全局视觉与布局规范

### 2.1 Figma 画板

| 场景 | Frame 尺寸 | 内容规则 |
|---|---|---|
| 移动端基准 | 390 × 844 | 主要设计基线，内容区左右 16px |
| 小屏验收 | 375 × 812 | 不出现页面级横向滚动 |
| 大屏手机 | 430 × 932 | 内容宽度随屏幕增长 |
| 桌面端 | 1440 × 1024 | 中央内容区最大 1120px，左右留白 |

### 2.2 字体与文字样式

字体回退：

```text
中文：PingFang SC / Noto Sans SC / Microsoft YaHei / system-ui
英文与数字：Inter / system-ui
时间码：Inter，启用 tabular numbers
```

Figma Text Styles：

| Style | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `Display/Mobile` | 24/32 | 700 | 页面主标题 |
| `Heading/Section` | 20/28 | 700 | 区域标题 |
| `Heading/Card` | 16/24 | 600 | 卡片标题、问题标题 |
| `Body/Primary` | 15/24 | 400 | 主体说明、反馈 |
| `Body/Secondary` | 14/21 | 400 | 次级说明 |

| `Button` | 15/20 | 600 | 按钮 |
| `Timecode` | 13/18 | 600 | 时间码 |

移动端正文不得小于 14px。所有文字图层必须保留字体、字号、行高、字重和颜色属性，供开发读取。

### 2.4 间距、圆角和触控

- 间距基线：4、8、12、16、24、32px。
- 页面区域间距：24px；卡片内边距：16px。
- 卡片圆角：12px；按钮圆角：10px；状态胶囊：999px。
- 主要触控目标最小 44 × 44px。
- 主按钮移动端固定全宽；桌面端最大 320px。
- 阴影克制，优先用边框和层级留白。

### 2.5 全局响应式原则

- 移动端双视频保持左右并排时，每侧必须完整显示人物；空间不足时允许视频视口上下堆叠，但共享时间轴仍只有一条。
- 桌面端视频区采用双列，状态区和报告区最大宽度 1120px。
- 弹层在移动端使用全屏或底部抽屉，桌面端使用最大 720px 对话框。
- 长文件名最多一行，超出省略；完整名称可通过辅助提示查看。
- 任何区间节点、状态文案和按钮不得因为中文长文案发生裁切。

## 3. 全局交互与权限规则

### 3.1 单页导航

页面不使用 URL 路由切换。主要状态通过内容替换、页面内滚动和弹层实现：

```text
P01 上传
→ P02 自动处理
→ P03 人物选择（条件分支）
→ P04 手动校准（条件分支）
→ P05 比对就绪
→ P06 分析中
→ P07 结果回看
```

P08、P09 和 O01 可从相关状态进入。

### 3.2 无账号权限说明

- MVP 无登录和角色权限。
- “权限不足状态”主要指浏览器无法读取文件、当前任务访问凭证失效或删除任务凭证缺失。
- 不出现“请登录”“会员权限不足”等文案。
- 无权限访问当前任务时统一提示：“本次任务已失效，请重新添加视频。”

### 3.3 焦点与无障碍

- 弹层打开后焦点进入标题；关闭后返回触发按钮。
- 支持 Escape 关闭非破坏性弹层。
- 错误与状态变化使用 `aria-live`，但频繁播放进度不播报。
- 差异节点必须有可访问名称，例如：“高优先级差异，00:08 到 00:11，Wave 到腰胯时断了一下”。
- 颜色不是唯一信息来源。

## 4. P01 双视频上传工作台

### 4.1 页面名称和页面目标

页面名称：双视频上传工作台。
页面目标：让用户在首次进入后快速理解需要添加哪两段视频，并完成合规文件选择。

### 4.2 目标用户

首次使用或准备新一次分析的舞蹈爱好者。

### 4.3 进入前置条件

- 用户打开 DanceMirror H5。
- 当前会话中没有完整的双视频任务，或用户已删除旧素材。

### 4.4 页面信息层级

1. 品牌和价值说明。
2. 老师示范与我的练习两个上传入口。
3. 拍摄和文件要求。
4. 当前步骤 CTA。
5. 隐私与数据说明入口。

### 4.5 页面区域划分

- Sticky Header。
- 首次使用说明。
- 双视频上传区。
- 文件规格与拍摄提示。
- 主行动区。
- 隐私说明入口。

### 4.6 组件、文案和功能

| 组件名称 | 类型 | 中文文案 | 功能 |
|---|---|---|---|
| AppHeader | Header | `DanceMirror` / `把明显差异讲清楚` | 品牌与页面定位 |
| PrivacyLink | TextButton | `数据如何处理` | 打开 P08 |
| FirstUseHint | InfoCard | `准备两段视频：老师示范和你的练习。老师视频需要有清晰音乐，你的练习尽量全身入镜、机位固定。` | 首次使用说明 |
| TeacherUploadCard | UploadCard | `老师示范` / `添加老师视频` / `需包含清晰背景音乐` | 选择老师视频 |
| UserUploadCard | UploadCard | `我的练习` / `添加我的练习视频` / `建议全身入镜、机位固定` | 选择用户视频 |
| FileRule | Caption | `支持 MP4、MOV；单个视频最长 3 分钟，最大 500MB` | 展示输入限制 |
| PrimaryAction | Button/Primary | 默认：`请先添加两段视频` | 展示下一步状态 |

已选择视频卡文案：

- 状态：`等待上传`
- 操作：`更换视频`
- 删除按钮无障碍名称：`删除老师视频` / `删除我的练习视频`

### 4.7 按钮响应

- 点击上传卡：打开系统文件选择器。
- 点击 `更换视频`：未处理中直接打开文件选择器；处理中先打开 O01。
- 点击删除：打开 O01。
- 点击 `数据如何处理`：打开 P08。
- 主按钮在双视频未齐时不响应，并通过文案说明缺少项。

### 4.8 输入校验规则

- 仅接受 MP4、MOV。
- 单文件不得超过 500MB。
- 可读取时长不得超过 3 分钟。
- 选择取消后保持原状态，不显示错误。
- 老师视频没有音轨属于服务端处理错误，不在文件选择阶段假定通过。
- 不把文件名、路径或视频内容写入埋点。

校验错误文案：

- 格式：`暂不支持这个视频格式，请选择 MP4 或 MOV。`
- 大小：`视频超过 500MB，请压缩后重新选择。`
- 时长：`视频超过 3 分钟，请截取需要分析的片段。`
- 无法读取：`无法读取这个视频，请重新选择或换一个文件。`

### 4.9 页面跳转关系

- 两段视频校验通过 → P02。
- 打开隐私 → P08。
- 浏览器不支持文件能力 → P09。

### 4.10 默认状态

双上传卡为空，主按钮禁用，文案为 `请先添加两段视频`。

### 4.11 空状态

- 双空：主按钮 `请先添加两段视频`。
- 仅老师：主按钮 `还需添加我的练习视频`。
- 仅用户：主按钮 `还需添加老师视频`。

### 4.12 加载状态

文件元数据读取时，卡片显示 `正在读取视频信息…`，替换和删除暂时禁用。

### 4.13 错误状态

错误显示在对应上传卡内部，不集中显示在页面底部；保留 `重新选择` 操作。

### 4.14 禁用状态

- 元数据读取时禁用同一卡片重复选择。
- 双视频未齐时主按钮禁用。
- 禁用按钮保留可读文案，不只降低透明度。

### 4.15 权限不足状态

文案：`无法读取所选视频，请重新选择并允许浏览器访问文件。`
操作：`重新选择视频`。

### 4.16 移动端和桌面端适配

- 移动端上传卡左右并排；小于 375px 或内容拥挤时上下排列。
- 桌面端双卡等宽并排，卡片高度一致。
- 说明文字移动端放在卡片下方，桌面端放在区域右侧。

### 4.17 关键交互说明

- 上传卡整块可点击，删除按钮点击不得冒泡触发文件选择。
- 选择视频后立即显示本地首帧/封面，不等待上传完成。
- 已选择视频必须显示角色，避免用户混淆老师与本人。

### 4.18 埋点建议

- `dm_upload_card_click`：`video_role`
- `dm_video_select_result`：`video_role/result/error_code/input_format/size_bucket/duration_bucket`
- `dm_video_replace_click`：`video_role/task_state`
- `dm_privacy_open`：`entry=upload`

### 4.19 验收标准

- 用户无需阅读技术说明即可区分两段视频角色。
- 双视频未齐时不能进入处理。
- 所有输入限制都有就近中文错误。
- 375px 宽度无横向滚动和文字裁切。

## 5. P02 自动处理状态

### 5.1 页面名称和页面目标

页面名称：自动处理状态。
页面目标：让用户清楚系统正在完成上传、转码、音轨对齐和人物检测，不需要理解技术细节。

### 5.2 目标用户

已选择两段有效视频，正在等待系统准备分析的用户。

### 5.3 进入前置条件

老师与用户视频均通过客户端校验。

### 5.4 页面信息层级

1. 双视频当前状态。
2. 总体处理进度。
3. 当前正在处理的步骤。
4. 可执行操作：替换、删除、取消。
5. 失败后的恢复入口。

### 5.5 页面区域划分

- 双视频缩略预览。
- ProcessStepper。
- 音轨对齐状态卡。
- 人物检测状态卡。
- 主行动区。

### 5.6 组件、文案和功能

| 组件 | 类型 | 中文文案 | 功能 |
|---|---|---|---|
| VideoStatusCard | StatusCard | `老师视频上传中 36%` / `我的练习正在统一格式` | 单视频处理进度 |
| ProcessStepper | Stepper | `上传视频` / `统一格式` / `自动对齐` / `识别人物` | 展示总体阶段 |
| AlignmentStatus | StatusCard | `正在自动寻找两段视频中的同一段音乐…` | 音轨进度 |
| SubjectStatus | StatusCard | `正在识别画面中需要跟踪的人物…` | 人物检测进度 |
| ProcessingHint | Caption | `你可以离开当前区域查看视频；更换素材会取消本次处理。` | 说明可操作边界 |
| PrimaryAction | Button/Primary | `正在准备视频` | 禁用态主按钮 |
| CancelTask | Button/Secondary | `取消本次处理` | 打开 O01 |

成功文案：

- `两段视频已准备好`
- `已自动对齐`
- `已找到单一人物`
- `检测到多人，需要你确认`

### 5.7 按钮响应

- `取消本次处理` → O01。
- `更换视频` / 删除 → O01；确认后取消旧任务并回 P01。
- 检测到多人时 `选择人物` → P03。
- 自动对齐失败时 `手动对齐` → P04。

### 5.8 输入校验规则

本页不新增文本输入。任何异步结果必须校验 `taskId` 与当前视频版本；旧任务不得更新页面。

### 5.9 页面跳转关系

- 多人 → P03。
- 自动对齐失败 → P04。
- 所有前置完成 → P05。
- 阻断错误 → P09。

### 5.10 默认状态

上传和转码先出现；音轨与人物步骤显示 `等待视频准备完成`。

### 5.11 空状态

若任一视频意外被清空，立即取消任务并回 P01 partial 状态。

### 5.12 加载状态

使用阶段式进度，不伪造精确总百分比。单视频上传可展示真实百分比，转码和分析展示阶段状态。

### 5.13 错误状态

- 上传失败：`上传中断，请检查网络后重试。`
- 转码失败：`这个视频暂时无法处理，请重新上传或换一个视频。`
- 老师无音轨：`老师视频没有可识别的背景音乐，请更换老师视频。`
- 自动对齐失败：`没有找到可靠的音乐对应位置，可以手动选择同一个动作起点。`

### 5.14 禁用状态

- 当前阶段按钮处理时禁用重复触发。
- 主 CTA 在人物和音轨未完成前禁用。

### 5.15 权限不足状态

若当前任务访问凭证失效：`本次任务已失效，请重新添加视频。`
按钮：`返回重新添加`。

### 5.16 移动端和桌面端适配

- 移动端 Stepper 纵向排列，当前步骤展开说明。
- 桌面端 Stepper 横向排列，双视频状态并排。

### 5.17 关键交互说明

- 音轨对齐和人物检测可并行。
- 替换素材后所有旧进度立即变为取消，不出现“旧任务完成”闪回。
- 状态变化使用柔和过渡，不使用庆祝动画。

### 5.18 埋点建议

- `dm_processing_stage_view`：`stage/video_role`
- `dm_processing_result`：`stage/result/error_code/duration_ms`
- `dm_processing_cancel_click`：`stage`
- `dm_recovery_action_click`：`error_code/action`

### 5.19 验收标准

- 用户能说清楚系统当前在做什么。
- 自动对齐过程可感知。
- 失败后有明确下一步。
- 替换视频后旧任务不会回写。

## 6. P03 目标人物选择

### 6.1 页面名称和页面目标

页面名称：目标人物选择。

## 7. P04 手动动作校准

### 7.1 页面名称和页面目标

页面名称：手动动作校准。
页面目标：自动音轨对齐失败时，让用户用直观方式指定两段视频中的同一个动作起点。

### 7.2 目标用户

用户视频无音轨、音质较差或自动音乐匹配失败的用户。

### 7.3 进入前置条件

3. 用户视频起点。
4. 同步预览。
5. 确认结果。

### 7.5 页面区域划分

- 标题与两步说明。
- 双视频预览。
- 各自时间轴和起点按钮。
- 同步预览控制。
- 底部确认区。

### 7.6 组件、文案和功能

标题：`手动对齐动作起点`。
说明：`分别把两段视频停在同一个动作的开始位置，我们会从这里同步播放。`

| 组件 | 类型 | 中文文案 | 功能 |
|---|---|---|---|
| TeacherAnchor | VideoAnchorPicker | `老师示范` / `设为老师起点` | 保存老师时间 |
| UserAnchor | VideoAnchorPicker | `我的练习` / `设为我的起点` | 保存用户时间 |
| AnchorStatus | StatusText | `老师起点：00:12.40` | 展示已选时间 |
| PreviewSync | Button/Secondary | `预览同步效果` | 同步播放 4 秒 |
| Confirm | Button/Primary | `确认对齐` | 保存手动校准 |
| RetryAuto | TextButton | `重新尝试自动对齐` | 重新发起自动匹配 |
| Cancel | Button/Secondary | `返回` | 回 P02 |

### 7.7 按钮响应

- `设为老师起点`：保存老师当前时间并显示状态。
- `设为我的起点`：保存用户当前时间。
- `预览同步效果`：两段视频从选定点同步播放 4 秒后暂停。
- `确认对齐`：生成共享时间轴并返回 P05。
- `重新尝试自动对齐`：清除手动点，返回 P02 working。

### 7.8 输入校验规则

- 两个起点都必须存在。
- 起点必须位于各自视频有效时长内。
- 两个起点计算后必须存在至少 0.5 秒共同区间。
- 数字时间由系统生成，不要求用户输入偏移秒数。

错误文案：

- `还需要选择老师视频的动作起点。`
- `还需要选择我的练习视频的动作起点。`
- `这两个起点之后没有可对比的共同片段，请重新选择。`

### 7.9 页面跳转关系

- 确认 → P05。
- 返回 → P02 manual_required。
- 重试自动 → P02 working。

### 7.10 默认状态

两段视频暂停在系统建议时间；两个起点均未确认，主按钮禁用。

### 7.11 空状态

若用户视频无音轨，显示提示：`没有检测到可用音轨，请直接选择同一个动作的开始位置。`

### 7.12 加载状态

预览准备中：`正在准备同步预览…`；所有起点按钮禁用。

### 7.13 错误状态

视频无法 seek：`暂时无法定位这个视频，请重新加载或更换视频。`

### 7.14 禁用状态

- 未选齐两个起点时 `预览同步效果` 与 `确认对齐` 禁用。
- 预览播放中禁用重新设置起点，显示 `停止预览`。

### 7.15 权限不足状态

任务失效：`本次视频已失效，请重新添加后再校准。`

### 7.16 移动端和桌面端适配

- 移动端双视频上下排列，避免画面过窄。
- 桌面端双视频左右并排。
- 底部确认区移动端固定，桌面端位于内容末尾。

### 7.17 关键交互说明

- 不默认暴露 `offsetSec` 数字输入。
- 用户拖动单侧视频时另一侧暂停。
- 只有预览时才按两个起点同步驱动。

### 7.18 埋点建议

- `dm_manual_align_view`：`reason_code`
- `dm_manual_anchor_set`：`video_role/time_bucket`
- `dm_manual_preview`：`result`
- `dm_manual_align_confirm`：`shared_duration_bucket`

### 7.19 验收标准

- 不理解偏移秒数的用户也能完成校准。
- 双起点未选齐时不能确认。
- 确认后两段视频可按共享时间轴播放。

## 9. P06 动作分析中

阶段文案：

### 9.13 错误状态

- 结构化分析失败：`暂时无法完成动作比较，请重试或更换视频。`

- 网络中断：`网络连接中断，正在尝试恢复…`

### 9.14 禁用状态

- 取消请求提交后按钮显示 `正在取消…` 并禁用重复操作。

`本次分析任务已失效，请重新添加视频。`
按钮：`返回上传`。

### 9.16 移动端和桌面端适配

- 移动端阶段列表纵向。
- 桌面端阶段横向，视频摘要左右并排。
- 等待页面不使用占满全屏的大型动画。

### 9.17 关键交互说明

- 页面切后台后任务继续，返回时恢复真实状态。
- 取消后任何迟到结果不得打开 P07。
- 模型失败是 fallback，不是全局失败。

### 9.18 埋点建议

- `dm_analysis_start`
- `dm_analysis_stage_view`：`stage`
- `dm_analysis_cancel`：`stage/result`

### 9.19 验收标准

- 用户知道当前阶段且可以取消。
- 模型失败时自动进入兜底报告。
- 旧任务结果不会覆盖已取消或已替换的任务。

`这一遍最明显的问题`

`你的上半身节奏基本跟上了。最明显的差异出现在 00:08：老师的 Wave 会继续传到腰胯，你在胸口后就停住了。`

**问题卡**

- 标题：`Wave 到腰胯时断了一下`
- 时间：`00:08—00:11`
- 优先级标签：`优先修正`
- 老师表现：`老师的动作从肩膀连续传到胸、腰和胯。`
- 我的表现：`你的动作到胸口后变短，腰胯没有继续接上。`
- 建议：`先暂停在 00:08，用 0.75 倍速练 4 组“肩—胸—腰—胯”。`
- 折叠按钮：`为何这样判断`
- 展开标题：`判断依据`
- 展开示例：`在 00:08—00:11，老师的躯干动作连续向下传递，你的腰胯变化明显更小。该结论仅用于舞蹈练习参考。`

**练习计划**

- 标题：`先练这一小段`
- 步骤 1：`暂停在 00:08，单独练肩、胸、腰、胯的传递。`
- 步骤 2：`用 0.75 倍速连续练 4 组。`
- 步骤 3：`重新录一遍时保持全身入镜。`

**操作按钮**

- `更换老师视频`
- `更换我的练习视频`
- `删除本次数据`

不得出现 `重新比对` 和任何评分。

### 10.7 按钮响应

- 点击差异节点：定位到区间起点、暂停双视频、激活对应问题卡。
- 播放进入区间：节点高亮放大，工作台下方自动切换对应分析。
- `为何这样判断`：原位展开依据摘要；再次点击文案为 `收起判断依据`。
- 更换视频 → O01。
- 删除本次数据 → P08 删除确认。

### 10.8 输入校验规则

- mismatches 数量 1–3。
- 每条必须有 start/end/title/severity/teacherObservation/userObservation/advice。
- end 必须大于 start，且位于共享时长内。
- 质量不足片段不得生成动作结论，应进入 trackingGaps。
- 模型返回字段异常时使用已校验的结构化兜底报告。

### 10.9 页面跳转关系

- 更换视频 → O01 → P01/P02。
- 数据说明/删除 → P08。
- 任务失效 → P09。
- 本页问题切换不改变 URL。

### 10.10 默认状态

- 第一条、最高严重度问题默认激活。
- 视频暂停在该问题区间起点。
- 判断依据默认折叠。

### 10.11 空状态

没有可信问题时：

- 标题：`这次没有找到足够可信的动作差异`
- 说明：`可能是人物没有完整入镜、遮挡较多，或两段视频没有对齐到同一段动作。`
- 操作：`重新选择人物`、`调整视频对齐`、`更换视频`

不得为了填满页面生成虚假问题。

### 10.12 加载状态

报告数据加载时显示：

- 双视频骨架占位。
- 文案：`正在打开本次分析…`
- 不显示空的问题卡。

### 10.13 错误状态

- 报告字段异常：`本次反馈暂时无法完整展示，已保留基础分析结果。`
- 视频加载失败：问题文字仍可查看，并提供 `重新加载视频`。
- 追踪丢失：`用户视频 00:18—00:21 未识别到完整身体`。

### 10.14 禁用状态

- 视频未加载时禁用播放与节点定位。
- 删除中禁用所有数据相关操作。
- 旧报告 stale 时所有节点禁用，提示 `正在生成新的分析结果`。

### 10.15 权限不足状态

`本次报告已失效或已被删除，请重新添加视频。`
按钮：`返回上传`。

### 10.16 移动端和桌面端适配

- 移动端顺序：总结 → 视频 → 时间轴 → 当前问题 → 练习。
- 桌面端视频与当前问题可左右分栏，时间轴横跨视频区。
- 问题列表移动端纵向，桌面端可使用侧栏，但激活关系必须一致。

### 10.17 关键交互说明

- high 节点：红色圆点 + `优先修正`。
- medium 节点：橙色菱形 + `明显差异`。
- low 节点：黄色短线 + `可以优化`。
- trackingGap：灰色斜纹区间 + 警告图标。
- 多节点重叠时 high > medium > low；同级按开始时间。
- 不展示模型原始思维链，只展示依据摘要。

### 10.18 埋点建议

- `dm_report_view`：`report_source/problem_count/tracking_gap_count`
- `dm_difference_node_activate`：`trigger=play|click/severity/problem_index`
- `dm_issue_evidence_toggle`：`action=expand|collapse/problem_index`
- `dm_practice_plan_view`
- `dm_report_recovery_click`：`action`

### 10.19 验收标准

- 报告只展示 1–3 个明显问题且按重要性排序。
- 节点、视频和问题卡三者保持同步。
- 播放进入区间时自动展示对应问题。
- 没有任何用户评分。
- 所有反馈为真实中文，可直接交付开发。

## 12. P09 阻断错误与兼容提示

### 12.1 页面名称和页面目标

页面名称：阻断错误与兼容提示。
页面目标：当当前设备或服务无法继续时，给出原因和可执行恢复路径。

### 12.2 目标用户

浏览器不支持、网络不可用、任务失效或服务异常的用户。

### 12.3 进入前置条件

发生无法在当前局部模块恢复的阻断错误。

### 12.4 页面信息层级

1. 明确错误标题。
2. 非技术化原因。
3. 推荐恢复动作。
4. 支持范围。
5. 返回入口。

### 12.5 页面区域划分

- ErrorIllustration/Icon。

- Primary Recovery Action。

浏览器不支持：

网络中断：

- 标题：`网络连接中断`

### 12.14 禁用状态

检测进行中禁用重复恢复按钮。

### 12.15 权限不足状态

### 12.16 移动端和桌面端适配

### 12.17 关键交互说明

- 不显示堆栈、HTTP 状态码或浏览器 API 名称。

### 12.18 埋点建议

- 用户不需要理解技术错误码。

5. 报告节点点击/播放激活 → 对应分析切换。
6. 报告 → 删除本次数据 → 双空状态。
7. 浏览器不支持 → 阻断错误 → 恢复/返回。

# DanceMirror PRD

## 1. 产品定位

DanceMirror 是一个帮助舞蹈初学者上传练舞视频，并通过 AI 快速发现动作问题、对比老师示范、生成可执行训练建议的移动端产品。

一句话定位：

> AI 舞蹈复盘助手，帮你看懂为什么自己跳得不像老师。

## 2. 用户与场景

核心用户：

- 18-35 岁女性舞蹈爱好者
- 常见舞种：K-pop、Jazz、Hip-hop、Urban
- 经常上舞蹈课、录视频、课后反复复盘
- 需要更快知道自己哪里不标准、哪里不好看、下一次该练什么

典型场景：

1. 用户上完课后拿到自己的练舞视频。
2. 她反复看视频，但只能感觉「不太像老师」，说不出原因。
3. 她上传自己的视频和老师参考视频。
4. AI 生成复盘报告，指出关键时间点、动作差异、发力问题和练习建议。
5. 用户第二天按建议练习，再次上传，形成成长记录。

## 3. 核心问题

现在用户的复盘方式主要是：

- 自己反复暂停、放大、对比
- 发给老师等反馈
- 发到社群或小红书求建议

痛点不是「不知道自己跳得不好」，而是：

> 知道不好，但不知道为什么不好，也不知道下一步怎么改。

## 4. MVP 目标

验证用户是否愿意上传舞蹈视频，并认为 AI 复盘报告有帮助。

MVP 成功信号：

- 用户愿意上传至少 1 段练舞视频
- 用户认为报告里至少 1 条建议「说中了」
- 用户愿意根据建议再练一次
- 用户愿意保存或分享报告卡片

## 5. MVP 功能

必须有：

1. 上传自己的练舞视频
2. 可选上传老师参考视频
3. 选择舞种：K-pop / Jazz / Hip-hop / Urban
4. 选择训练目标：动作准确 / 发力控制 / 节奏卡点 / 出片表现
5. AI 复盘报告
6. 报告包含：
   - 综合反馈
   - 最大的 3 个动作问题
   - 对应视频时间点
   - 和老师/标准动作的差异
   - 为什么会这样
   - 今天该练什么
   - 机位、光线、穿搭等出片建议

暂不做：

- 社区
- 直播
- 课程商城
- 复杂会员体系
- 多运动扩展
- 专业医疗或康复建议
- 自动剪辑发布

## 6. 信息架构

第一版页面：

1. 首页 / 上传页
2. 分析等待页
3. 复盘报告页
4. 历史记录页，后续版本

## 7. 报告原则

报告要像一个温和但准确的舞蹈老师，不像考试打分器。

反馈表达：

- 先给最大问题，再解释原因
- 每条建议必须可执行
- 避免只说「手抬高一点」这种低价值反馈
- 尽量使用「差异解释」：老师怎么做、你怎么做、为什么看起来不同

## 8. 风险

产品风险：

- AI 反馈太泛泛，用户觉得没价值
- 舞蹈动作复杂，单靠 2D 视频难以准确判断
- 视频上传涉及隐私与存储成本

应对：

- MVP 先做高质量报告内容与交互，不急着承诺全自动精确姿态识别
- 明确提示 AI 反馈仅用于训练参考
- 尽量让用户本地预览，后端只在用户确认分析后处理视频

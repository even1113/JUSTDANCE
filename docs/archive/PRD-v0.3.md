## 0. 文档说明

### 0.1 证据标记

本文所有产品描述按以下三类标记：

- **【原型已确认】**：可以从当前代码、当前页面或外部 HTML 线框直接确认“这一事实或方案确实存在”。它是证据状态，不等于产品已批准；若来自外部旧线框，会额外标记“外部线框存在，不代表当前需求”。
- **【合理推断】**：根据现有页面目标、交互链和数据处理方式可以推导，但仍需产品确认。
- **【需求缺口】**：代码和原型没有定义，或不同证据相互冲突，需要补充产品决策。

### 0.2 证据优先级

发生冲突时，本次反向整理按以下顺序判断当前真实产品：

1. 当前运行代码与测试
2. 当前 `DESIGN_SYSTEM.md`、`TECH_SPEC.md`、`AI_SPEC.md`
3. 归档前的 v0.2 PRD
4. `TASKS.md`、`README.md`
5. 外部低保真 `dancemirror_wireframes.html`

【原型已确认｜当前实现】当前产品是一个无 URL 业务路由的 H5 单页应用，主要状态由内存对象、DOM 的 `hidden/disabled`、`data-state` 和提示文案共同驱动。

【原型已确认｜当前实现】当前核心链路是：

```text
添加老师视频和我的视频
→ 自动或手动完成音轨偏移
→ 可选手动框选本人
→ 浏览器端逐帧姿态分析
→ 页面内展开报告
→ 点击问题时间点回看
→ 使用原视频重新比对，或删除后重新选择视频
```

【需求缺口】项目尚未建立正式的产品状态枚举、运行时报告 schema 校验、埋点或用户研究数据，因此本文不补造转化率、准确率、时长上限、文件大小上限等指标。

## 1. 产品背景与目标

### 1.1 产品背景

【原型已确认｜当前实现】页面将“老师示范”和“我的练习”放在同一个逐帧比对工作台中，并把音轨对齐、姿态识别、差异解释和练习建议串为一次复盘。

【合理推断】DanceMirror 解决的不是“播放舞蹈视频”，而是把用户难以人工完成的双视频定位、节奏对齐和动作差异归纳，转换成可以立即练习的反馈。

### 1.2 产品目标

【原型已确认｜当前实现】当前功能目标是让用户无需注册登录，在浏览器中完成一次“上传双视频—分析—查看复盘报告”的闭环。

【原型已确认｜当前实现】当前技术目标是优先在浏览器本地处理视频、音频和姿态数据；可选的 Gemini 调用只接收结构化分析结果，不接收原始视频或原始关键点坐标。

【合理推断】产品价值目标是帮助用户理解“我和老师具体哪里不同、为什么观感不同、下一次先练什么”，而不是提供单一考试分数。

【需求缺口】尚未定义可被采集和验证的产品成功指标。旧文档中的“建议说中、愿意再练、愿意截图分享”可作为研究问题，但当前没有埋点、问卷或判定口径。

## 2. 目标用户及核心使用场景

### 2.1 目标用户

【合理推断】核心用户是拥有老师示范视频和本人练习视频、希望课后自主复盘的 C 端舞蹈爱好者。

【合理推断】用户不需要理解姿态识别、音频互相关或 DTW；她只需要能选择视频、确认对齐、查看差异和执行练习建议。

【需求缺口】年龄、性别、舞种、舞龄、设备档位和付费意愿没有被当前代码或页面验证。归档 PRD 曾描述“18–35 岁女性、K-pop/Jazz/Hip-hop/Urban”，本版不将其视为已确认事实。

### 2.2 核心使用场景

1. 【合理推断】课程结束后，用户同时拥有老师示范和自己的练习录像，希望快速复盘。
2. 【原型已确认｜当前实现】用户在移动浏览器打开产品，无需登录即可分别添加两段本地视频。
3. 【原型已确认｜当前实现】用户点击发起音轨自动对齐；无法可靠对齐时，可手动输入偏移秒数。
4. 【原型已确认｜当前实现】用户视频加载后即可手动画框并保存“本人已锁定”的界面状态；【需求缺口】该矩形目前没有实际限制 MediaPipe 的检测区域。
5. 【原型已确认｜当前实现】系统提取姿态、对齐动作序列、计算指标并生成页面内报告。
6. 【原型已确认｜当前实现】用户点击报告时间点，同时定位老师视频和用户视频，并高亮对应问题卡。
7. 【合理推断】用户依据练习计划修正动作后，希望替换自己的视频再次比对。
8. 【需求缺口】当前没有明确的录制入口、练习计时器、完成训练状态或“只替换我的视频”的独立 CTA。

## 3. 用户痛点

【合理推断】核心痛点包括：

- 人工来回拖动两段视频，难以找到同一拍和同一动作帧。
- 只能感知“看起来不像”，难以拆解为姿态、节奏、幅度或控制问题。
- 即使看见差异，也不知道应该先改哪一处、用什么速度和次数练习。
- 多人、遮挡、镜像、机位和视频起点不同会增加自助复盘难度。

【原型已确认｜当前实现】产品已经针对前三项提供音轨偏移、逐帧控制、结构化问题和练习计划。

【需求缺口】“用户最在意哪类反馈”“分数是否有帮助”“框选本人是否可理解”等问题没有用户研究证据，不能直接写成已验证需求。

## 5. 核心用户流程

### 5.1 当前主流程

```text
S0 upload.empty
  └─ 添加任一视频
      ↓
S1 upload.partial
  └─ 添加另一段视频
      ↓
S2 upload.ready_unaligned
  ├─ 用户点击自动对齐 → S3 alignment.working
  │                          ├─ 成功 → S4 alignment.ready
  │                          └─ 失败 → S3E alignment.error
  └─ 用户应用手动偏移 ─────────────────→ S4 alignment.ready

只要用户视频已加载，即可并行进入主体标记子流程：
subject.unlocked
  └─ 打开框选 → subject.selecting
                    ├─ 确认 → subject.locked_ui
                    └─ 取消 → 恢复此前锁定或未锁定

S4 alignment.ready
  └─ 开始逐帧比对
      ↓
S5 analysis.processing
  ├─ 本地分析失败 → S5E analysis.error
  └─ 本地报告成功
       ├─ 无 API Key → S6 report.ready
       └─ 有 API Key
            ├─ 模型成功 → S6 report.ready
            └─ 模型失败 → 使用本地报告 → S6 report.ready

S6 report.ready
  ├─ 点击问题时间点 → S7 report.issue_focused
  ├─ 直接再次点击分析 → S5 analysis.processing
  ├─ 重新比对 → S4 alignment.ready
  └─ 删除任一视频 → S0 或 S1，并重置对齐与报告
```

### 5.2 流程规则

- 【原型已确认｜当前实现】两段视频上传顺序不受限制。
- 【原型已确认｜当前实现】没有音轨结果时不能开始姿态分析。
- 【原型已确认｜当前实现】手动框选 UI 是用户视频加载后的可选并行步骤，不是系统自动多人识别分支，也尚未真实限制检测区域。
- 【原型已确认｜当前实现】模型调用不是本地分析的前置条件；模型失败不应让整次分析失败。
- 【原型已确认｜当前实现】重新比对保留当前素材；删除视频则重置与该素材关联的分析状态。
- 【原型已确认｜当前实现】报告生成后，分析按钮仍可直接再次触发分析；新任务启动时旧 `latestReport` 和问题时间点不会预先清空。
- 【合理推断】练习后的理想回路应保留老师视频，只替换用户视频，再重新对齐和分析。
- 【需求缺口】当前没有显式“替换视频”按钮，用户只能先删除再重新添加；也没有描述哪些状态在“只替换我的视频”后应保留。
- 【需求缺口】直接再次分析若失败，旧问题时间点仍可能可点击并指向旧报告数据；需要定义“开始时清空、失败时恢复”或“旧报告持续可见”的一致规则。

## 7. 各页面与组件功能说明

### 7.1 应用头部

【原型已确认｜当前实现】展示品牌和“逐帧比对”定位；头部在页面滚动时保持 sticky。

【原型已确认｜当前实现】设置按钮打开 API 配置弹层。

【需求缺口】正式 C 端版本是否展示技术型 API 设置入口未确认。

### 7.2 双视频工作台

【原型已确认｜当前实现】工作台固定区分“老师示范”和“我的练习”，初始均为空。

【原型已确认｜当前实现】空面板点击后触发浏览器文件选择器；非空面板展示视频、骨架 Canvas、原生播放控制、前后时间步进、时间码、文件名、大小和删除按钮。前后按钮每次固定移动 1/30 秒，不读取视频真实帧率。

【原型已确认｜当前实现】任一视频为横屏时，双列布局切换为上下堆叠。

【需求缺口】没有上传中、视频解码中、替换、删除确认、撤销删除、文件大小/时长/编码预校验状态。

### 7.3 音轨对齐面板

【原型已确认｜当前实现】展示 `idle / working / ready / error` 四种状态。

【原型已确认｜当前实现】自动对齐使用两段视频的音频起音包络和互相关计算偏移；成功展示用户视频偏移和可信度。

【原型已确认｜当前实现】失败后可输入 `-30` 至 `+30` 秒的手动偏移，步进为 `0.05` 秒。

【原型已确认｜当前实现】自动对齐期间只禁用自动对齐按钮，手动偏移和删除视频入口仍可操作。

【需求缺口】手动偏移点击后立即显示 ready，但共同区间是否合法要到分析阶段才校验，状态语义不完整。

【需求缺口】正在执行的自动对齐没有取消或任务版本校验；其异步结果可能覆盖用户随后应用的手动偏移或删除素材后的状态。

### 7.4 分析启动区

【原型已确认｜当前实现】说明分析会经过音轨对齐、33 个身体关键点、姿态、幅度、节奏和控制差异计算。

## 12. 异常流程和边界条件

1. **视频类型与兼容性**
   - 【原型已确认】当前只检查 MIME 是否以 `video/` 开头。
   - 【需求缺口】未定义文件大小、时长、分辨率、编码、帧率、旋转信息、无音轨和损坏文件的前置规则。

2. **短视频与音轨**
   - 【原型已确认】自动对齐默认要求至少 8 秒共同音频窗口。
   - 【需求缺口】小于该时长的视频没有专属提示，可能被统一解释为对齐失败。

3. **手动偏移**
   - 【原型已确认】允许 ±30 秒，步进 0.05 秒。
   - 【需求缺口】没有在“应用偏移”时即时校验共同区间。

4. **浏览器兼容性**
   - 【原型已确认】姿态分析依赖 `requestVideoFrameCallback`、Web Audio API、Canvas、MediaPipe WASM 和远程模型。
   - 【需求缺口】没有支持浏览器列表、最低版本或兼容性降级策略。

5. **长视频与性能**
   - 【原型已确认】老师和用户视频按 1× 播放速度顺序提取逐帧姿态。
   - 【合理推断】长视频可能造成较长等待和较高内存占用。
   - 【需求缺口】没有时长限制、抽样策略、后台处理、取消或超时规则。

6. **多人和主体锁定**
   - 【原型已确认】MediaPipe 配置 `numPoses: 1`，没有多人候选、人物 ID 或自动主体排序。
   - 【需求缺口】“自动追踪画面中最明显的运动主体”和“只分析框选的人”是超出当前实现的文案承诺。

7. **局部追踪丢失**
   - 【原型已确认】单帧无姿态时会跳过，只有整段没有任何姿态帧才失败。
   - 【需求缺口】没有丢失比例、丢失时间区间、低置信度提示或重新框选入口。

8. **镜像与视角**
   - 【原型已确认】系统会比较正常与左右镜像后的序列成本。
   - 【需求缺口】没有透视校正、机位自动修正或修改原视频的“视角校正”能力。

9. **音轨对齐并发**
   - 【原型已确认】自动对齐期间只禁用自动对齐按钮，手动偏移和视频删除仍可触发。
   - 【合理推断】较晚返回的自动对齐结果可能覆盖用户刚应用的手动偏移，或把删除素材后的页面重新写为 ready/error。
   - 【需求缺口】需要为对齐任务增加取消、输入锁定、任务版本或过期结果丢弃规则。

10. **分析并发**
   - 【原型已确认】分析时只禁用分析按钮，其他文件和对齐控件未整体锁定。
   - 【合理推断】分析期间修改输入可能产生竞态。
   - 【需求缺口】需要定义取消、输入锁定和过期任务丢弃规则。

11. **模型输出**
    - 【原型已确认】模型响应只做 JSON 提取和解析。
    - 【需求缺口】字段缺失或类型错误可能导致报告渲染异常；需要正式 schema 校验和本地报告回退。

12. **报告持久化**
    - 【原型已确认】最新报告写入 localStorage，但页面启动时不读取。
    - 【需求缺口】刷新后视频丢失、旧报告仍可能残留，保留策略和清除规则未定义。

13. **直接再次分析与旧状态**
    - 【原型已确认】报告完成后，用户可以不点击“重新比对”而直接再次点击分析。
    - 【原型已确认】新分析开始时只隐藏报告区，不会预先清空内存中的 `latestReport` 和问题时间点；若新分析失败，旧时间点仍可能保持可点击。
    - 【需求缺口】需要定义重分析开始、成功和失败三个节点对旧报告、时间点及视频定位状态的保留或恢复规则。

14. **重置语义**
    - 【原型已确认】删除任一视频会清除音轨、报告和骨架；删除用户视频还会清除框选。
    - 【原型已确认】重新比对保留视频、偏移和框选，只清除报告和骨架；老师视频定位到 0 秒，用户视频定位到 `offsetSec`。
    - 【需求缺口】“选择新视频”“只换我的视频”“重新比对”三个动作尚未形成清晰、独立的产品语义。

## 13. MVP 范围

### 13.1 已确认的 MVP

- 【原型已确认】移动端优先、无需登录的单页 H5。
- 【原型已确认】老师视频和用户视频均为必需输入。
- 【原型已确认】本地预览、删除后重选、独立播放和固定 1/30 秒时间步进控制。
- 【原型已确认】自动音轨对齐，失败后可手动偏移。
- 【原型已确认】浏览器端 MediaPipe 姿态提取、归一化、镜像候选、DTW 和结构化指标。
- 【原型已确认】本地报告是必需能力；外部模型总结是可选增强。
- 【原型已确认】报告在当前页面内展开，包含总结、关键问题、时间点、老师/我的差异、练习计划和复盘建议。
- 【原型已确认】评分只能作为报告内次级信息，不能替代差异解释。
- 【原型已确认】问题时间点可定位双视频并高亮问题。
- 【原型已确认】重新比对可保留当前素材和对齐状态。

### 13.2 MVP 发布前必须裁决的需求缺口

- 【需求缺口】框选本人是降级为“辅助标记”，还是修复为真正限制检测区域。
- 【需求缺口】报告是否必须固定输出 3 个问题。
- 【需求缺口】是否把 API 设置保留在普通用户界面。
- 【需求缺口】`safetyNote` 必须在 UI 展示还是仅保留数据字段。
- 【需求缺口】支持浏览器、视频格式、时长和文件大小范围。
- 【需求缺口】分析期间能否取消，以及输入是否必须锁定。
- 【需求缺口】本地报告与 API Key 的保留、清除和隐私说明。
- 【需求缺口】分析失败后的恢复是复用现有分析按钮，还是增加独立“重试分析”和“更换对应视频”按钮。
